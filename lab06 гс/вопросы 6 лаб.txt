1. Принцип установления соединения с сервером Oracle по сети
Процесс соединения (т.н. «рукопожатие») выглядит следующим образом:
Клиент (например, SQL*Plus или приложение) инициирует запрос, используя строку подключения (алиас или EZConnect).
Запрос по сети (TCP/IP) приходит на сервер, на конкретный порт (обычно 1521).
На сервере этот порт слушает специальный процесс — Listener (Прослушиватель).
Listener перехватывает запрос и проверяет, существует ли запрашиваемый сервис (имя базы данных) и доступен ли он.
Если все хорошо, Listener запускает для клиента серверный процесс (Server Process) или передает клиента диспетчеру (в режиме Shared Server).
Listener передает адрес этого процесса клиенту, и дальше клиент общается с выделенным серверным процессом напрямую. Listener возвращается к прослушиванию новых запросов.
2. Назначение конфигурационных файлов
SQLNET.ORA (Клиент и Сервер): Файл профиля сети. Задает общие правила игры: методы аутентификации, приоритет методов разрешения имен (искать сначала в файле или подключаться сразу по IP), настройки логирования и тайм-аутов.
TNSNAMES.ORA (Клиент): «Адресная книга» клиента. Сопоставляет короткое, понятное имя (псевдоним/Alias, например MYDB) с полным сетевым дескриптором (IP-адрес, порт, имя сервиса). Нужен, чтобы не вводить длинные адреса вручную.
LISTENER.ORA (Сервер): Конфигурация Прослушивателя. Этот файл лежит только на сервере (в вашем случае — внутри Docker-контейнера). Он говорит Listener'у: «Слушай порт 1521, используй протокол TCP и обслуживай базу данных с таким-то именем».
3. Виды соединений
Основные архитектурные типы соединений:
Выделенное соединение (Dedicated Server):
На каждое подключение клиента сервер создает отдельный процесс в оперативной памяти.
Характеристика: Самый надежный и быстрый для тяжелых запросов. Требует много памяти сервера. Используется по умолчанию.
Разделяемое соединение (Shared Server):
Клиенты подключаются не к выделенному процессу, а к Диспетчерам. Запросы попадают в общую очередь, и пул серверных процессов обрабатывает их по мере поступления.
Характеристика: Экономит память сервера при тысячах одновременных подключений («тонкие» клиенты), но работает чуть медленнее для долгих операций.
DRCP (Database Resident Connection Pooling):
Пул соединений на стороне сервера. Эффективно для веб-приложений (PHP/Python), которые часто открывают и закрывают короткие сессии.
4. Что такое строка подключения?
Это строка, которую пользователь передает клиенту (SQL*Plus) для входа в систему. Она обычно содержит имя пользователя, пароль и идентификатор базы данных.
Примеры:
С использованием TNS-алиаса: scott/tiger@MYDB
Метод Easy Connect (без настройки файлов): scott/tiger@192.168.1.50:1521/orcl
5. Что такое дескриптор подключения?
Это техническая часть описания соединения, понятная сетевому слою Oracle. Обычно она скрыта внутри файла tnsnames.ora под псевдонимом.
Дескриптор описывает ГДЕ находится база (ADDRESS) и КАК к ней обратиться (CONNECT_DATA).
Пример дескриптора:
code
Text
(DESCRIPTION=
  (ADDRESS=(PROTOCOL=tcp)(HOST=localhost)(PORT=1521))
  (CONNECT_DATA=(SERVICE_NAME=ORCL))
)
6. Расшифровка аббревиатуры TNS
TNS = Transparent Network Substrate (Прозрачная сетевая подложка).
Это собственная сетевая технология Oracle, которая позволяет разным приложениям Oracle общаться друг с другом по сети, скрывая детали конкретных сетевых протоколов (TCP/IP, IPC, и т.д.).
7. Назначение утилиты Oracle Net Manager
Это графическая утилита (GUI), которая поставляется вместе с клиентом или сервером Oracle.
Назначение: Упростить создание и редактирование файлов tnsnames.ora, listener.ora и sqlnet.ora. Она позволяет настраивать подключения через визуальный интерфейс («древовидное меню»), что избавляет от синтаксических ошибок (пропущенных скобок), часто возникающих при ручном редактировании текстовых файлов.
8. Этапы запуска и останова экземпляра Oracle
Запуск (STARTUP):
NOMOUNT (Запуск экземпляра): Oracle считывает файл параметров (spfile или init.ora), выделяет оперативную память (SGA) и запускает фоновые процессы. Доступа к данным еще нет.
MOUNT (Монтирование): Экземпляр считывает контрольный файл (Control File). Теперь Oracle знает имена и пути к файлам данных и журналам, но они все еще закрыты. На этом этапе выполняются административные задачи (восстановление, переименование файлов).
OPEN (Открытие): Oracle открывает все файлы данных и файлы журналов (Redo logs). Проверяется целостность базы. База данных становится доступна обычным пользователям.
Останов (SHUTDOWN):
NORMAL: Ждет, пока все пользователи сами отключатся. (Может висеть вечно).
TRANSACTIONAL: Ждет завершения текущих транзакций, но новые не пускает. Затем отключает пользователя.
IMMEDIATE (Самый частый): Откатывает незавершенные транзакции, принудительно разрывает сессии пользователей и корректно закрывает файлы.
ABORT: «Выдергивание шнура из розетки». Мгновенно убивает процессы. Файлы не закрываются корректно. При следующем запуске потребуется автоматическое восстановление (Instance Recovery).
9. Имя группы пользователей Windows для администраторов
Группа называется ORA_DBA.
Пользователи, включенные в эту группу локальной операционной системы Windows, могут подключаться к базе данных с правами администратора без ввода пароля, используя команду:
sqlplus / as sysdba
(Механизм аутентификации NTS).
