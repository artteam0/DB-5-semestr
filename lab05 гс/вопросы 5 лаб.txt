1. Расшифруйте аббревиатуру SGA.
SGA - System Global Area (Общая системная область) - это разделяемая область памяти, которую используют все процессы экземпляра Oracle для хранения кэшированных данных и управляющей информации.

2. Основные пулы памяти SGA и их назначение:
Buffer Cache - кэширует блоки данных из таблиц и индексов

Shared Pool - кэширует SQL-запросы, PL/SQL-код, информацию о структуре данных

Redo Log Buffer - буфер для записей журнала повтора перед записью на диск

Large Pool - используется для крупных операций (параллельные запросы, RMAN, UGA)

Java Pool - хранение состояния Java-объектов и классов

Streams Pool - используется Oracle Streams для буферизации сообщений

3. Параметры SGA_MAX_SIZE и SGA_TARGET:
SGA_MAX_SIZE - максимальный размер SGA, который нельзя превысить без перезапуска инстанса

SGA_TARGET - текущий целевой размер SGA, которым автоматически управляет Oracle (ASMM - Automatic Shared Memory Management)

4. Назначение буферного кэша инстанса:
Буферный кэш хранит копии блоков данных, прочитанных с диска. Это уменьшает количество физических операций ввода-вывода и ускоряет доступ к данным.

5. Назначение пулов KEEP, DEFAULT и RECYCLE буферного кэша:
KEEP - для часто используемых таблиц, которые должны всегда оставаться в памяти

DEFAULT - стандартный пул для всех объектов

RECYCLE - для редко используемых больших таблиц, которые не должны вытеснять полезные данные

6. Принцип вытеснения блоков буферного кэша (LRU):
LRU (Least Recently Used) - алгоритм, при котором первыми вытесняются блоки, к которым дольше всего не было обращений. Блоки перемещаются в "горячий" конец списка при каждом обращении.

7. Принцип вытеснения блоков таблицы, созданной оператором CREATE TABLE … CACHE:
Таблицы с опцией CACHE помещаются в "горячий" конец LRU-списка при полном сканировании, но все равно могут быть вытеснены при нехватке памяти (в отличие от таблиц в пуле KEEP).

8. Как изменить размеры пулов:
sql
-- Для ручного управления
ALTER SYSTEM SET db_cache_size = 1G;
ALTER SYSTEM SET shared_pool_size = 500M;

-- Для автоматического управления (ASMM)
ALTER SYSTEM SET sga_target = 2G;

9. Какие пулы допускают изменение размеров:
Buffer Cache (db_cache_size, db_keep_cache_size, db_recycle_cache_size)

Shared Pool (shared_pool_size)

Large Pool (large_pool_size)

Java Pool (java_pool_size)

Streams Pool (streams_pool_size)

10. Назначение процесса LISTENER:
Listener (слушатель) - это отдельный процесс, который:

Прослушивает входящие подключения к БД

Перенаправляет соединения соответствующим серверным процессам

Поддерживает несколько протоколов (TCP/IP, IPC и др.)

11. Назначение утилиты lsnrctl:
Утилита управления слушателем. Основные команды:

start/stop - запуск/остановка

status - проверка состояния

services - список обслуживаемых служб

reload - перезагрузка конфигурации

12. Что такое сервис?
Сервис - это логическая группировка работы БД для определенных приложений или пользователей. Точка подключения клиентов к экземпляру.

13. Какие сервисы создаются автоматически:
SYS$BACKGROUND - для фоновых процессов

SYS$USERS - для пользовательских подключений по умолчанию

Сервис с именем БД (например: ORCL, XE)

14. Принцип работы dedicated и shared соединений:
Dedicated - каждому клиенту выделяется отдельный серверный процесс

Shared - несколько клиентов используют пул серверных процессов через диспетчеров

15. Назначение файла LISTENER.ORA:
Конфигурационный файл слушателя, содержащий:

Настройки портов и протоколов

Статическую регистрацию служб

Параметры безопасности и логирования

16. Основные фоновые процессы и их назначение:
PMON - монитор процессов (очистка аварийных сессий)

SMON - монитор системы (восстановление, очистка временных сегментов)

DBWn - запись измененных блоков на диск

LGWR - запись журнала повтора на диск

CKPT - обновление контрольных точек

MMON - сбор статистики для AWR

17. Что такое серверный процесс и как его просмотреть:
Серверный процесс - процесс, обрабатывающий запросы пользовательской сессии.

Просмотр:

sql
SELECT program, pid, spid, username 
FROM v$process 
WHERE background = 0;
